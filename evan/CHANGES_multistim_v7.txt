Changes for sound_tuning_multistim_fov_analysis_v7.py (2026-10-28)
====================================================================

Stage 1 only; v6 is unchanged. Statistics, response windows, v6 column names and trial archives
(schema_version multistim_v2) are the same as v6, so stage 2/3 v6 read v7 output unchanged.

1. Per-cell notes on every single-cell panel (individual_tuning_pages/<block>/ and the tuning
   panels of cell_reports/):
     - BF at each pure-tone level of the FOV, the pure_tones block level first
       ("BF: 70 dB 8.09 kHz · 75 dB 6.63 kHz"; "n.s." = not BF-eligible at that level);
     - BF (pure_tones level) relative to the block's center frequency or chord F0
       ("BF re band center (8 kHz): -0.29 oct"; FM center, band center, noise-pair A center, F0);
     - the selectivity index (as in v5/v6); noise pairs also the per-cell novelty-test q.
   Tuning pages are drawn in merge_fov_blocks() after all blocks are merged (analyze_block()
   returns their inputs in meta["_tuning_pages"], removed before fov_manifest.json is saved).
   Cell-report titles use three lines (session / ROI + BF note / responsive blocks); with five
   blocks the v6-style two-line title was cut off.

2. Other pure-tone levels in an FOV are analyzed instead of skipped. The pure_tones block level is
   chosen as in v6 (--pure-tone-level; default the level recorded in the most FOVs, ties -> closest
   to the other blocks' level). Each other level is analyzed the same way into
   fov_outputs/<FOV>/pure_tones_other_levels/<N>dB/ (archive, raster, profile, tuning pages) and
   merged as pure_<N>dB_* columns. split_pure_tone_levels() replaces keep_one_pure_tone_level().
   Seeds for the other levels are seed + 7919*(k+1); the main blocks keep v6's seeds.
   run_manifest.json: other_pure_tone_level_sessions; fov_manifest.json: other_pure_tone_levels.

3. New columns: pure_bf_eligible (responsive FDR & response at BF > 0 & q at BF < 0.05, as in the
   level-series branch and quick_bf_check_v1.py), pure_q_at_bf, pure_tones_level_db, and
   pure_<N>dB_bf_eligible / pure_<N>dB_q_at_bf for other levels. Existing columns (e.g.
   pure_bf_octaves_from_<fmr|bn|np>_center, argmax BF of every cell) are unchanged.

Notes:
   - The output folder is per subject / area / dates, so separate runs of different FOVs on one day
     share combined/, fov_manifest.csv and run_manifest.json (last run wins; --dry-run also
     rewrites the two manifests). fov_outputs/<FOV>/ folders coexist.
   - A run that includes an FOV with only a different pure-tone level can make the "most FOVs" rule
     choose that level for every FOV (20261022 with FOVs 1-3 chose 75 dB); run FOVs separately or
     pass --pure-tone-level.
   - sound_tuning_auto_analysis_v1.py still runs v6.

Validation: py_compile; note helpers on synthetic rows (BF per level, n.s., center offset,
novelty q); dry runs on imag041 20261022 (FOV1, FOV2, FOVs 1-3); full run on imag041 20261022 FOV1
(sessions 001-006; 468 cells; no failures; tuning-page counts match the responsive cells of each
block, 449 cell reports; a repeated run with the same seed reproduced all 268 columns of
fov_cell_results.csv); cell-report title fix checked by redrawing one report from saved outputs.
